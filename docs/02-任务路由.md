## 2. 语料怎么选

### 优先级

1. **同模型**：写 Seedance 2.5，优先 `model = seedance_2_5`；写 Seedance 2.0，优先 `seedance_2_0`。
2. **同题型**：单镜优先 `scenes` 与 VPL 主库；角色优先 `characters`；场景/道具优先 `locations` / `props`。
3. **同题材**：动作、爱情、广告、动画分开找，不要拿广告的分镜套打戏。
4. **同规模**：30 秒短片与 3 分钟 MV 的段落密度不同，优先同量级。

> **分类覆盖警告**：537 个项目只有 `all`，只有 6 个项目带 `scenes`。`--cat scenes` 返回 0 条时，去掉 `--cat`，改用 `--keyword`，不要判断“库里没有”。覆盖表见 [catalog/higgsfield-projects.md](../catalog/higgsfield-projects.md#分类覆盖)。

### 各语料适合什么

| 语料 | 最适合 | 不适合 |
|---|---|---|
| 项目 `scenes` | 看一部片子的分镜如何在时间上展开 | 直接当单条成片提示词 |
| 项目 `characters` / `locations` / `props` | 看角色、场景、道具设定怎么写细 | 看镜头运动 |
| 项目 `assets` | 看图生视频的资产与重跑记录 | 学叙事结构（碎片化） |
| 项目 `all` | 只在全量文件里出现、未归类的提示词 | 快速定位（量大） |
| VPL 主库 | 单条成片级提示词的整体写法 | 学完整项目工程 |
| VPL 通用区 | 补运镜、器材、表演、构图的零件 | 当完整提示词直接提交 |
| VPL 教程区 | 学工作流步骤 | 找具体镜头描述 |
| Seedance 方法 | 建立写作框架与判断标准 | 代替具体项目事实 |
| Higgsfield 三轨方法 | 查平台硬约束、术语、运镜型号、系列化打法 | 代替剧本 |
| 官方教程 / 博客 | 学完整工作流与官方口径 | 找现成镜头 |
| 全流程方法论 | 看一个项目从策划到交付的拆解 | 当逐条提示词库 |

## 3. 三条常用组合

### 组合 A：写一条 15 秒单镜

```text
SD25 02 通用结构
→ HF 视频 01 提示词结构（补块语法与配时）
→ VPL 主库同题材 3 条（结构）
→ 同项目 scenes 2 条（镜头密度）
→ 写 → 自检 → 引用
```

### 组合 B：写一场 5 镜打戏

```text
SD25 06 动作因果
→ HF 视频 04 动作与打戏
→ HF 视频 03 运镜与空间
→ SD25 10 连续转场
→ VPL 动作·打斗 3 条
→ 项目 KOK_BORU / HELL_GRIND 的 scenes 3 条
→ 写 → 检查每镜的受力与结果 → 引用
```

### 组合 C：角色总是变形

```text
SD25 按问题查（人物一致性）
→ SD25 03 参考分工
→ HF 视频 02 参考分工
→ 找同模型、同参考方式的失败记录
→ 写出“保留什么/替换什么/缺什么”的修正版
```

## 4. 不推荐的路径

| 做法 | 为什么不行 |
|---|---|
| 解压 611 个项目逐个读 | 816 MB 原文，且大部分与当前任务无关 |
| 只读索引摘要就动笔 | 摘要只有 80 字，丢失镜头关系与语气 |
| 拿 `assets` 里的碎片当完整分镜 | `assets` 是素材与重跑记录，不是叙事单位 |
| 同时读 20 条参考 | 风格互相打架，最后写成拼盘 |
| 用不同模型的参数互相套 | 入口、时长、参考方式不同，结论不可迁移 |
| 把 78 项目仓当全量 | 它只是 611 项目的子集，已被全量语料覆盖 |

## 5. 交付前的统一检查

- [ ] 主体、服装、场景、道具与当前项目一致。
- [ ] 每个动作有触发、过程、结果。
- [ ] 镜头运动有动机，起幅落幅清楚。
- [ ] 光影有方向，材质有受力反应。
- [ ] 声音服务叙事，不是音效清单。
- [ ] 没有把参考里的地名、人名、台词带进来。
- [ ] 末尾有参考来源与待确认项。
