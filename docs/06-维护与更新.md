# 维护与更新

> 这个库的价值在于“索引始终对得上原文”。任何改动都按下面的顺序走。

## 1. 日常改动

### 新增一个 Higgsfield 项目

1. 在本地数据包中准备好该项目的 JSONL。
2. 放到 `sources/higgsfield/prompts/<PROJECT>/prompts.jsonl.gz`，每行字段 `id/cat/type/model/prompt`。
3. 把 brief、README、官方 Skill 放到 `sources/higgsfield/projects/<PROJECT>/`。
4. 重跑 `python tools/build_catalog.py`。
5. 跑 `python tools/validate_kb.py`，全绿再提交。

### 修改方法页

1. 先改 `sources/higgsfield-knowledge-base/现行知识/` 或 `sources/seedance25-knowledge-base/现行知识/`。
2. 同步到 `sources/higgsfield-knowledge-base/现行知识/` 或 `sources/seedance25-knowledge-base/现行知识/`。
3. 如果改了页名或增删页，同步更新 `catalog/methods.json` 与相关导航页。
4. 跑校验。

### 新增一条 VPL 条目

1. 按原库规则追加到 `sources/video-prompt-library/AI-全库.jsonl`。
2. 重跑 `python tools/build_catalog.py`（会重建 VPL 索引）。
3. 跑校验。

### 新增一个技能

1. 放到 `skills/<技能名>/SKILL.md`。
2. 如果来自上游仓，同时放到 `sources/skills-repo/skills/<技能名>/`。
3. 重跑 `python tools/build_catalog.py`，更新 `catalog/skills.json`。
4. 跑校验。

## 2. 构建脚本

### `tools/build_catalog.py`

从源文件重算**全部**派生产物，无需其他脚本：

- `catalog/higgsfield-prompts.index.jsonl`（逐项目读 `prompts.jsonl.gz`）
- `catalog/higgsfield-projects.json` / `.md` / `.csv`
- `catalog/higgsfield-models.json`
- `catalog/video-prompt-library.index.jsonl`（读 `AI-全库.jsonl`）
- `catalog/methods.json`
- `catalog/skills.json`
- `index.json`
- `MANIFEST.json`

执行约 30–40 秒。**唯一真源是 `sources/`**：改了源文件就重跑它，`catalog/` 不要手改。

### `tools/kb.py`

只读工具，不修改任何文件：

- `stats` 读 `index.json`
- `search` 流式读两个索引
- `get` 按 ID 回读压缩文件

### `tools/validate_kb.py`

发布前必跑：

1. 必需文件是否存在。
2. 索引行数与 `index.json` 是否一致。
3. 每个项目的压缩文件行数是否与索引一致。
4. Markdown 相对链接是否可解析。
5. 是否含令牌、密钥、私钥。
6. 文档是否含本机绝对路径。

退出码 0 = 全绿。

## 3. 提交前检查清单

- [ ] `python tools/validate_kb.py` 返回 `OK`
- [ ] `index.json` 的 `updated` 已更新
- [ ] 新增或删除的项目已反映在 `catalog/higgsfield-projects.md`
- [ ] 新增方法页已进入 `catalog/methods.json`
- [ ] 新增技能已进入 `catalog/skills.json`
- [ ] 没有把 `.mimosa`、`.git`、临时文件、截图、视频带进来
- [ ] 没有把私人聊天、令牌、本机绝对路径写进正文

## 4. 不做的事

| 不做 | 原因 |
|---|---|
| 手改 `catalog/*.jsonl` | 下次构建会被覆盖，且容易与原文不一致 |
| 改写 `sources/` 原文 | 原文是证据；需要解释就写进方法页或 `docs/` |
| 把 78 项目仓重新加回来 | 已被 611 项目全量语料覆盖，重复且浪费空间 |
| 把图片、PDF、ZIP、视频放进仓库 | 体积大，GitHub 不适合；保留在本地工作区 |
| 用 `git add .` 一把梭 | 容易带入临时文件与私密内容；按目录检查后提交 |

## 5. 大改结构时

1. 先改本文件与 `AGENTS.md` 的目录说明。
2. 再改脚本。
3. 重建索引。
4. 跑校验。
5. 抽查 3 个项目、3 条 VPL、3 个方法页的链接与回读。
6. 提交信息写清楚：改了什么、影响多少条、校验结果。
