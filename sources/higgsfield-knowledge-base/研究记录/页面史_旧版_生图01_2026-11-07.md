# 生图/01 生图提示词方法

生图提示词的目标不是描述一张图，而是**立法一张底片**：把内容、空间、相机、光线、色彩全部钉死，让渲染器无从自由发挥。

## 核心律 [官方 S03 原文]

> `CONTROL THE IMAGE'S LOGIC, CONTENT, AND CAMERA. DIRECT THE LIGHT. DO NOT SIMULATE THE RENDERER.`

> `For Soul and Soul Cinema, trust the model to create cinematic exposure, material response, texture, colour nuance, highlight roll-off, shadows, and photographic finish. Give it coherent scene logic and art direction rather than a technical rendering recipe.`

**不要替渲染器干活**——不给 Kelvin 值、曝光档位、光照比、去噪指令、微对比映射、材质响应层，除非编辑匹配需要。

## 一、4-D 方法论 [官方 S03]

| 阶段 | 做什么 |
|---|---|
| **DECONSTRUCT** | 拆解请求：核心意图/图像功能/关键主体/场景/风格/构图/相机/必须读清的细节/输出格式/硬约束/参考件/已有定义/缺失项。硬约束与灵活创意分开。 |
| **DIAGNOSE** | 诊断请求：主体身份模糊？场景层级不清？缺少占用描述？建筑描述不足？物体特征缺失？位置冲突？比例不确定？镜头/视角缺失？风格标签模糊？可见文字未控？参考角色冲突？过约束抑制模型优势？→ 判定为 simple / controlled / complex / placement-sensitive / reference-dependent / edit-dependent。 |
| **DEVELOP** | 按请求类型选择技术：创意类→多解释内选最优；技术类→硬约束+可测量位置+Location Map；教学类→清晰结构+few-shot；复杂类→内部逐步推理+依赖先解决+编译后 preflight。 |
| **DELIVER** | 直接可用/连贯自然语言/保留硬约束/足够视觉特征/省略框架标签/无通用质量填充词/无重复指令。 |

### 上下文分层序（编译顺序）

```text
INTENT → HARD CONSTRAINTS → SCENE HIERARCHY → LOCATION MAP OR SUBJECT MAP
→ CAMERA → OBJECT AND MATERIAL CHARACTERISTICS → LIGHTING DIRECTION
→ TONAL AND COLOUR LOGIC → STYLE → TEXT AND OCCUPANCY CONTROL
→ FAILURE-SPECIFIC CONSTRAINTS
```

## 二、五道硬 Gate（Non-Negotiable Generation Defaults）

### Gate 1 · Empty Location Gate [官方]

场景为地点/室内/外观/街道/车库/厨房/仓库等，且用户未明确要求人物时：

```text
occupancy = empty
people_presence = forbidden
```

最终提示词必须显式写：
> `No people, silhouettes, faces, human figures, human-shaped reflections, mannequins, portraits that read as real occupants, or figures visible through windows, doors, mirrors, or screens.`

**不要推断**车库里有 mechanic、厨房里有 cook、街上有行人。人类活动通过维护过的物件、磨损、摆放、功能痕迹传达，不通过虚构的人。

### Gate 2 · Lens Gate [官方]

每条新生成提示词必须给：相机位置/高度（如空间有用）/观看方向/景别/全幅等效焦距/水平 FOV/畸变行为。

用户未给镜头时的默认表：

| 场景 | 焦距 | FOV |
|---|---|---|
| 平衡室内 | 32–35mm | 54–59° |
| 紧凑室内需更宽 | 24–28mm | 65–74° |
| 主体在环境中 | 35mm | 54° |
| 大型外观/工业空间 | 28–35mm | 54–65° |
| 人像/孤立主体 | 选较长镜头 | — |

默认光学指令：
> `Use a refined spherical lens with clean rectilinear rendering. Keep architecture and objects naturally proportioned. Distortion is off.`

**无变形宽银幕拉伸或水平耀斑条纹**，除非明确要求。

### Gate 3 · Style Gate [官方]

每条提示词**恰好一个**主风格。用户未给时默认：
> `cinematic editorial realism`

16 个风格档：cinematic editorial realism / naturalistic cinematography / restrained prestige drama / noir chiaroscuro / luminous golden naturalism / documentary observational / architectural minimal / monumental atmospheric / period tableau / clinical institutional / surreal physicalism / expressionist colour / graphic symmetry / tactile industrial / polished commercial / intimate domestic realism。

**绝不混用多个主风格。绝不只用标签——把风格特征带入构图、物件选择、光线方向、色板、状态。**

### Gate 4 · Text Gate [官方]

只对**天然带文字的载体**（招牌/菜单/车牌/标签/屏幕/包装/钟表/门牌号）给精确文本（语言+大小写+载体+位置+换行）。不对普通碗/布/家具/墙/工具宣布空白。

### Gate 5 · Location Tonal Gate [官方]

地点主导图和主体在场景中图，默认**中性中间调基底**：

> `Maintain a neutral photographic colour foundation with a broad, articulate middle register. Preserve the independent local colour of concrete, metal, glass, painted surfaces, vegetation, sky, and practical lights. Keep warm and cool source colours spatially contained near their actual sources. Build cinematic contrast through luminance, depth, surface reflectance, and natural falloff rather than a single full-frame tint.`

**禁止**全局 orange/cyan/teal/green/magenta/blue 色罩作为氛围捷径。**禁止** teal-and-orange 分离做默认。光源颜色空间限制在源头附近。

## 三、13 步强制工作流 [官方 S03]

```text
1. DETECT MODE（Generate / Edit / Reference Match / Cleanup / Diagnose）
2. APPLY HARD DEFAULTS（五道 Gate）
3. EXTRACT INTENT（功能/设定/主体/建筑/必读物件/位置/空间关系/时间天气/光线/风格/占用/文字/参考/变更/保护属性）
4. CLASSIFY SCENE HIERARCHY（Subject-Led 或 Location-Led）
5. BUILD LOCATION MAP（强制：FRAME LEFT → CENTRE → RIGHT × FOREGROUND → MIDGROUND → BACKGROUND）
6. BUILD SCENESPEC（26 字段内部结构，不暴露除非用户要求）
7. COMPLETE MISSING CHARACTERISTICS（保守连贯假设，不返回欠描述提示词）
8. CHECK PHYSICAL AND SPATIAL LOGIC
9. BUILD TONAL AND COLOUR LOGIC
10. SELECT ONE STYLE PROFILE
11. COMPILE NATURAL-LANGUAGE PROMPT
12. RUN PREFLIGHT（23 问）
13. OUTPUT（直接从 Create... 开始，不加 Prompt 标签）
```

### Location Map 内部模板

```text
FRAME LEFT
  foreground:
  midground:
  background:
FRAME CENTRE
  foreground:
  midground:
  background:
FRAME RIGHT
  foreground:
  midground:
  background:
```

空区定义用途（circulation / negative space / sightline / access route / subject separation / view into deeper space）。**不用虚构道具填空区。**

最终提示词必须保持同样的左→中→右顺序。用连贯散文（`on frame left` / `across the centre` / `in the lower foreground`）而非暴露标题。

### SceneSpec 26 字段

mode / scene_type / image_function / primary_style / occupancy / setting / architecture / location_map / camera / lens / composition / primary_subject / environmental_groups / spatial_relationships / lighting_direction / materials_and_state / palette / tonal_foundation / source_colour_containment / visible_text / reference_roles / edit_delta / protected_properties / likely_failure_risks

**禁止**用 `nice` / `cinematic` / `stylish` / `realistic` / `detailed` / `moody` 等占位词——必须替换为可观察特征。

### Preflight 23 问（答案为 no 则拒绝并修订）

1. 模式正确？2. 场地无请求人→occupancy 显式 empty？3. 提示词含 no-people 指令？4. 恰好一个主风格+可观察特征？5. 场地有完整左→右 Location Map？6. 最终提示词保持 frame left→centre→right 顺序？7. 各区前景/中景/背景关系清楚？8. 建筑与重要物件超越类别标签？9. 主要物件完整（形态/材质/状态/位置/朝向/关系）？10. 可见性/分离/重叠受控？11. 空区受保护不被虚构道具填充？12. 小道具成组非随机枚举？13. 相机/焦距/FOV/畸变显式？14. 通道与进出路线可理解？15. 光线有方向不过度工程化？16. 中性中间调基底（除非风格要求）？17. 冷暖源空间限制？18. 材质保持独立局部色非全局色罩？19. 文字节载体精确文本？20. 非文字载体无空白规则？21. 编辑与参考锁保留？22. 每句话改变图像或阻止高概率失败？23. 内部工作流语言不在最终提示词中？

## 四、编译顺序 [官方 S03]

### Subject-Led（主体主导）

```text
图像功能与主体 → 主体比例/位置/朝向/可见性 → 场地特征 → 相机/镜头/FOV
→ 左区环境 → 中区环境与主体关系 → 右区环境 → 主体状态/动作
→ 光线方向 → 中性色基底与局部色 → 风格特征与材质色板
→ 空场或人物控制 → 精确文本 → 仅高概率失败约束
```

### Location-Led（场地主导）

```text
图像功能与场地身份 → 建筑/比例/材质/状态 → 相机/镜头/FOV
→ 整体构图/深度/流通 → 左：前→中→后 → 中：前→中→后 → 右：前→中→后
→ 光线方向 → 中性色基底 → 风格特征与色板 → 强制 no-people → 精确文本 → 失败约束
```

## 五、提示词长度标准 [官方 S03]

| 类型 | 词数 |
|---|---|
| 简单主体 | 250–400 |
| 受控场地 | 500–750 |
| 复杂主体环境 | 600–850 |
| 密集 placement-sensitive | 只在新增细节控制可见决策时更长 |

**不可缩短掉**：建筑、物件特征、位置、相机、镜头、FOV、占用、空间关系、精确文本、编辑锁。
**应移除**：重复结论、同义词堆叠、渲染器术语、穷举失败清单、不影响画面的次要计数。

## 七、References 与 Edit Locks [官方 S03]

### 引用优先级（冲突时从上到下）

1. 用户显式约束
2. 底图身份与受保护结构
3. 分配的主体/产品参考
4. 构图
5. 场地
6. 风格
7. 氛围/色板/材质

风格参考**永不**覆盖身份或显式布局。

### Edit Locks

硬保留（Hard preserve）：主体身份与数量/构图/相机与透视/裁切与画布/姿态/主要布局/受保护文字与区域。
上下文保留（Contextual preserve）：曝光与调色/光线方向/阴影与反射/材质外观/背景/景深。
上下文属性仅在编辑逻辑需要时改变。

### Cleanup

非生成修复。可修：伪影/污渍/断裂渐变/重复细节/畸形边缘/压缩损伤/不想要的合成纹理/小几何缺陷。
**禁止**：裁切/重框/重新布景/添加/移除/替换/重定位/重设计/改主体数量或姿态/换背景/改变意图光线。

## 十、常见错误

1. 用 `cinematic` / `beautiful` / `high quality` 等占位词代替可观察特征
2. 忘写 Empty Location Gate 的 no-people 全句
3. 全局色罩代替局部光源色彩（teal-and-orange  shortcut）
4. 给 Kelvin 值/光照比/去噪指令（替渲染器干活）
5. 用艺术家/导演/工作室名做风格指令
6. 暴露 FRAME LEFT / LOCATION MAP / SCENESPEC 等内部标签
7. 同义堆叠（cinematic + filmic + movie-like + film still 连用）
8. 枚举所有可能失败而非只写高概率失败约束

## 常见错误·官方来源补充 [官方 S21 seedance4k]

## 2026-11-04 孤儿提示词深挖增补（792 条孤儿中发现的四种新模式）

### 8. LOCATION ASSET 内景版——跨资产 UUID 链接 [案例 ANERNEQ 12×]

LOCATION PLATE 之外还有 **LOCATION ASSET** 块——场地的内景版本，通过 UUID 链接外景资产：

> LOCATION ASSET — INSIDE THE BURNT YARANGA <<<image_1>>>, THE MORNING AFTER. This is the INTERIOR of the dead collapsed dwelling from the camp exterior asset <<<80d01cde-…>>> — **same world, same hour, same weather.**

加上 STATE OF THE WORLD 块（fire is DEAD / ember pockets / NO people）和 TIME AND LIGHT — MATCHED TO THE EXTERIOR（跨资产光线匹配）。

### 9. 3D PREVISUALIZATION BLOCKOUT 前置流程 [案例 ANERNEQ 16×]

**先生成 clay previz，再做真图**——两步法：

> A 3D PREVISUALIZATION BLOCKOUT RENDER of a film composition — clean previz clay-render style: all figures and surfaces as untextured matte light-grey dummies with soft ambient occlusion, no faces, no clothing detail, simple geometry — **but with the SHOT'S CAMERA AND LIGHTING reproduced exactly, aspect ratio 21:9.**

3D previz 锁定构图+相机+光线 → 后续真实生成以 previz 为参考。**这是电影工业 pre-viz 流程在 AI 提示词中的复刻。**

### 10. 俄语编辑指令模式 [案例 ANERNEQ]

nano_banana_2 / gpt_image_2 的编辑指令用**俄语短句**（46-48 字符）：
> в футаж 1 добавь больше костей как в футаже 2（在镜头 1 加更多骨头，像镜头 2 那样）
> пусть у него где руки будут варюшки на веревках（让他的手臂上有绳子挂的护腕）

**短句俄语编辑指令直接操作参考图**——非英语工作流确认。

### 11. Match/Keep identical 编辑模式 [案例 ANERNEQ 12×+8×+8×]

编辑模式的第三种形态（区别于 Cleanup 和 TEXTURE PASS）：
> Keep everything identical: same person, same clothing, same pose, same location... only change [X].
> Match the visual world of the reference image.
> Edit this image: keep EVERY object, surface, and lighting exactly as shown — only [change Y].

## 2026-11-04 海报排版立法增补 [案例 S25 the-locked-room 131 赞，全文逐字]

### 12. 电影海报文字排版立法（繁体中文提示词实证）[案例 the-locked-room 1,601c 全文]

海报图提示词的**文字与排版专项立法**（Text Gate 的海报级深化）：

1. **唯一文字声明**：`「密室」必須是整張海報唯一中文文字`——画面内文字白名单制
2. **字体材质描述**：`使用厚重、銳利、克制、略帶金屬磨損與水泥顆粒感的繁體中文字體；字形必須完整、端正、精確，不要書法、血字、霓虹、故障字體或廉價恐怖片風格`——字体按质感描述 + 否定排除五种廉价风格
3. **中英文字体对位关系**：`「THE LOCKED ROOM」使用寬字距、現代、全大寫的高級電影海報英文字體，寬度與中文主標題形成整齊視覺關係`——双语字体的视觉关系立法
4. **负空间排版**：`Tagline、中文片名及英文片名全部放在右半部金屬門的深色負空間，保持足夠安全邊界，不能貼近畫面邊緣`——文字放负空间 + 安全边界
5. **文字性质声明**：`文字應像專業電影海報排版，不是貼在門上的實體油漆或場景內標記`——排版 vs 场景内文字的本体论区分
6. **文字不遮挡主体**：`不得讓任何文字遮擋Alice的臉、頭髮、眼睛、嘴部或身體輪廓`
7. **三组文字拼写合同**：`海報只可出現以下三組文字，必須拼寫完全正確、清晰可讀。不得加入演員名、導演名、日期、影展桂冠、假credits、logo、水印`
8. **只调色不改内容**：`只透過專業電影海報級調色、光影控制、局部對比、細緻35mm電影顆粒、自然暗角及排版提升海報感，不改寫原本場景內容`——海报化=调色+排版，不加不减场景

**繁体中文全文提示词**（非英语工作流的第二语言实证，继 ANERNEQ 俄语后）——图像任务可用中文提示词直写。

### 13. 编辑对偶块：PRESERVE EXACTLY + ONLY CHANGE [案例 S26 the-golden-tree 39×+39×]

编辑模式的块化对偶形态——保什么（PRESERVE EXACTLY×39）与改什么（ONLY CHANGE×39）**成对出现、次数相等**，互为合同两半。配套量化锁：`Bat count stays small, 6 to 8, never a large swarm.`（数量区间锁）+ `Lightning stays as diffuse sky glow only — no bolt shape ever appears.`（形态锁）。

### 14. 非英语工作流第三语言：波斯语 [案例 S26 quran-heals-the-hearts]

### 15. 几何面=身份：风格本体的身份立法 [案例 S27 the-coat 840 全唯一 1.0×]
