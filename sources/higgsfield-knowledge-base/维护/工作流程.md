# 知识库工作流程（知识树 v2 · 如何让知识生长）

> 2026-11-05 v2 定稿：重写制 + skills 果实层 + 实践记录回写。铁令不变：**原文优先、收录源逐字全读、不出错**。

## 一、输入面（材料从哪来）

02区 项目包（all_prompts.jsonl + brief + README.json）｜05区 官方 skill、博客、教程｜用户提供的范本库与使用反馈。原件只读，进库先在 来源登记 领 Sxx 号。

## 二、逐字铁令（不可绕过）

凡动过一个来源，其全部收录源必须**逐字读完**（jsonl 每条、brief 全文、skill 全文、博客全文）；总结、抽样、机读统计**不算**读完；读完之前不得产出该来源的知识结论。

## 三、生长链（五站）

1. **逐字读** → 台账销账（read:true + findings）+ 事件记录 E 号追加
2. **发现** → 研究记录（批量日志，编号发现 + 全库首见标注；笔记不是规则）
3. **项目收官 → 现行知识重写**：该域页按「短摘录→好在哪→迁移法」重写为**当前态蒸馏**；旧版全文移 研究记录/页面史_旧版_*（一字不删）；来源登记补 S 行
4. **同步**：现行知识为唯一源，node 维护/sync_skills.js 刷 references（禁手改 references）
5. **实践**：用户使用后回写 实践记录/任务索引 → 触发页修订（补充/修正/合并/替换/撤回；现有页装不下才新增）

## 四、页纪律

语义命名（轨道/两位序号-域名）；⏳ 空号=生长位，不回填不跳用；每页必备：状态头（trial/validated）+ 证据分层 + [案例]带项目名 + 待验证（生长点）；一域一页，禁同义页。

## 五、维护纪律（每次变更后）

入口同步（AGENTS/README/索引/按任务查/按问题查/index.json 不留旧描述过夜）→ 事件 E 追加 → check_kb.js 全绿 → sync_skills.js（改了方法页必跑）→ 扩展矩阵 23 项 `node 维护/_kb_fullaudit_v2.js`（含活文档旧编号残留=0）→ 源指纹审计 `node 维护/_audit_full.js`（覆盖 T3 #33-40 八项目）。收尾链以 知识库建设蓝图.md 生长链五站为 canonical。

## 六、编号与登记

来源 Sxx 只增不改、跨类混用一序列（S41/S42/S43=DST/SBS/7L 三战役；下一个项目来源=S44 顺延）；新旧名对照关系查事件记录。

## 七、状态流转与复审

trial（文本归纳）→ validated（多项目印证 + 用户出片确认）→ deprecated（被替代）。方法页 180 日复审；新项目入库 / 用户失败反馈 / 站点改版触发提前复审。
