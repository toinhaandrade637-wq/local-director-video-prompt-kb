# 持续学习与使用

## 先把内容学进来

收到一批提示词，连同台词、参考职责、修改版本、用户解释与反馈一起读完整。先理解整段怎样成立：人物想做什么、动作怎样接上、摄影在看什么、光声与环境怎样参与。再把可迁移的写法补到相关现行页。

每页尽量给出具体方法与短例。用“原文短摘录 → 哪些词句在起作用 → 下次怎样迁移”，或用清楚标记的改前改后对照。原文保留在来源层，研究保留推导，现行知识承接可用写法。新材料可以支持、深化、修正或合并既有认识，内容多少由实际需要决定。

## 直接用于写作

查方法或写提示词时，从任务导航进入所需页面，结合其中的示例写出当前内容。保留既定故事、人物与台词。普通写稿不用先建任务表、刷新哈希或运行维护脚本；需要回看过程时再留简要记录。

得到用户评价或实际结果后，先写清具体观察及条件，直接修订相关方法和示例。文字分析、用户经验、真实结果各自保留来源；把维护性质的说明留在记录里，不给每页和每份成稿重复加免责声明。

## 按批次整理与同步

同一批材料或一组关联修改，合并处理一次：

1. 读通受影响的正文与例子，确认摘录准确、讲解具体、相关页说法相容。
2. 更新必要来源与一条批次事件；已有审读元数据随这次整理更新。
3. 生成索引和Skill参考，运行一次文件检查，同步私有仓库。

既有工具负责整理，学习不用等待全库完成某种验证阶段。检查器回归只在维护代码变更时运行；没有新的维护问题就不增加脚本和测试。实际使用中的有效修订比反复证明检查器自身更有价值。

完整材料、示例和现行方法都在仓库里，按[来源档案](../资料库/索引.md)、[知识索引](../现行知识/索引.md)各自查阅。历史验证与待解问题继续保留在维护目录，遇到对应任务再查。
