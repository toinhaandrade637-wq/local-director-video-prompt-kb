# Lint 与复审约定

2026-10-29执行方式调整：以下保留既有工具能力供维护时查阅，不作为日常学习或写稿的前置流程。普通小改先完成正文；同一批材料集中记录、构建并检查一次。工具与29项回归保留，不再扩建；检查器自身回归只在维护代码变更时运行。

入库分析负责判断材料怎样影响方法；Lint负责持续检查组织关系。当前没有采用五维评分，也不需要为本次审查另造评分模型。

## 一份正文与可生成入口

- 方法正文及其元数据：现行知识页面。
- 来源元信息：`资料库/来源登记.json`；可读登记由catalog生成。
- 维护事件：`维护/events.jsonl`；更新记录与总索引的最近活动由它生成。
- 已知疑点与语义复核：`维护/semantic_review.json`；待验证问题页由其中issues生成，不两边独立改状态。
- `index.md`与`index.json`由catalog生成；主题、任务、问题导航仍按实际使用场景维护，生成总表不掩盖缺少路由的问题。
- Skill参考由方法正文生成，只包含trial／validated页；停用页不进入新Skill。

批次同步时构建索引与Skill参考，再运行一次文件检查。维护代码改动时才执行已有回归；CI也按代码变更决定是否运行回归。文件名不是效果证据，分数也不代替清理与验证。

方法frontmatter使用明确的平面字段与行内列表：id、status、review、generation_validation、updated、reviewed_on、review_after、topics、sources。当前检查器不把这个受限格式宣称为完整YAML实现。trial可供试用；validated仍须明确证据及适用条件；deprecated／withdrawn只保留追溯，不继续向新任务推荐。

## 自动检查的边界

| 检查 | 处理 |
|---|---|
| 必需文件、发布清单、凭据形态、遗漏新方法 | 错误，修复后发布 |
| 元数据ID／枚举／日期／来源、重复键 | 错误，不能用非空代替合法性 |
| 链接文件、锚点、当前导航孤儿、停用页仍被推荐 | 错误；AGENTS等特殊入口不当知识孤儿 |
| 生成索引／登记／事件视图／Skill快照过期 | 错误；回到主源修改再构建 |
| 已登记的同key、同scope有效声明相反 | 错误；先核对范围和来源，不机械二选一 |
| 到复审日期、needs-review、语义审读哈希落后 | 警告并给出页面，需按影响安排复核 |
| 已知但尚未解决的官方分歧 | 保留open、来源和下一步；不改成虚假的已解决 |

`--base-ref <提交SHA>`还会核对已有事件未被改写、删除，以及本次实质发布变更是否被新事件关联。生成文件由对应主源事件覆盖，避免事件记录自身无限递归。正常检查只因错误失败；`--strict-warnings`可用于需要逐项处理警告的场合。

## 什么算复核

`updated`是页面修改日；`reviewed_on`是文本方法复核日；`review_after`是维护提醒日。平台依赖默认30日、一般方法180日，这些是本库维护约定，不是知识有效期。发生来源变化、新的反例或实际失败时提前核对，不用等日历到期。

官方来源的`snapshot_date`、`text_reviewed_on`、`current_verified_on`分别记录取得版本、读过文字、核对当前能力。未做实时核对时最后一项保持null，不能因为改了知识页就变成“官方已最新验证”。

语义复核需阅读受影响正文和相关页，比较同一对象、时段、入口与条件下的结论。`semantic_review.json`保存审读范围的正文哈希、少量关键声明及已知疑点；它是复核证据，不是独立规则正文。正文变动会提示重新审读，不能自动更新哈希当成已理解。

静态程序不能保证自由文本完全无矛盾、外链永远可访问、来源真实或生成效果成立。发现疑点保留状态、依据、影响范围和后续动作；有据才关闭。关闭记录不删历史，错误事件用新增更正事件追溯。
