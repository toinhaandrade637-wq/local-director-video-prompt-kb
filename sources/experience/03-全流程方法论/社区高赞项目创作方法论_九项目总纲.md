# 社区高赞项目创作方法论 · 十一项目总纲（9 高赞 + 2 教学型）

> 来源：社区 42 个公开项目按**赞数门槛**（赞≥80 且资产≥100 件）筛出的 9 个高赞项目，02 区 9 个数据包（3386 资产 / 3350 带提示词 / 1039 去重提示词），全部与预扫描对账一致。
> 定位：与 03 区 11+1 篇官方方法论形成**"官方 vs 社区创作者"对照系**——官方片是"体系工程学"的满分范本，这 9 个项目是"同一套语法在真实创作者手里长什么样"。

## 〇.5 整体画面风格 DNA（社区九项目的视觉宪法谱系）

### 1. 风格前缀的"方言化"（词频证据）
- **TOP_UP_AD**（@adilinthewild，官方教程作者本人）：`Style: 8K IMAX. Photorealistic — no 3D render, no game engine, no game-cutscene aesthetic` ×57——与耳机/4K教程逐字同源，证明**官方教程句式就是社区实战标准**。它还叠加了类型片定制句：`Documentary-grade cinematography in the visual tone of mid-2000s practical robot suit commercials — real practical effects, real stunt actors in robot suits, NOT a video game render`（用"年代实拍质感"反渲染味）。
- **NALA**：`21:9` ×52 + `Kodak Vision3` ×51 + `anamorphic` ×66——全 9 个项目里唯一的**变形宽银幕胶片系 MV**，音乐片直接搬 LoveStory 现代段的宪法。
- **ONE_MORE_TIME / DUSK / THE_NEW_GIRL**：hundreds of `handheld`+`hard cut`，自然光派，提示词里几乎不写"风格"句——**用现场感参数替代风格宣言**。
- **ANIME_PRODUCTION**：`anime` ×352 / `cel-shad` ×48 / `manga` ×83——风格词密度型（每个 prompt 自带风格定义），配 seedream_v5_pro 图库路线。

### 2. <<<image>>> 引用密度 = 项目复杂度指标
| 项目 | <<<image>>> 出现 | 结构含义 |
|---|---|---|
| DUSK | 2242 | 每条提示词挂 5-10 张参考图（角色/服装/场景/道具全锚） |
| THE_NEW_GIRL | 629 | 双线剧集（special episode + ep1），角色场景全锁 |
| HUNTRESS | 249 | 角色锚 <<<image_1/2>>> + 生物锚 <<<image_3>>> |
| ACADEMY | 122 | 教学演示级引用 |
| 其余 | <30 | 单角色或纯风格项目 |

**规律**：引用密度越高，片越长、角色越多——社区创作者用**参考图数量**管理复杂度，而不是写更长的描述。

### 3. 提示词长度的两极分化
- DUSK 平均 **7055 字符**（官方 ONEIRIC 级别的工程强度）—— 社区创作者里也有"全锁链派"
- SOUL_CAROUSELS 平均 **1695 字符**—— 短 prompt 纯美学路线（glitter/twins/dream/surreal 系列轮播，一张图一个氛围）
- **没有"中等长度"**——社区两极化：要么全锁，要么纯感觉。

### 4. Folder 组织学（管窥创作流程）
- HUNTRESS：`Locations → SHOT1-5 → Character sheet → UI`——**按镜头编号组织**（类似 RED_FLAG 的分镜结构）
- THE_NEW_GIRL：`FINAL KEYFRAMES / FINAL GENERATIONS / SCENE-3`——**"关键帧→生成"两段式 + 迭代版次管理**（FINAL 前缀=收敛后的最终态）
- TOP_UP_AD：`SCENE1-11 + TESTS + ASS[ETS]`——广告逐场 + **TESTS 文件夹**（社区创作者也会保留实验区）
- DUSK：`episode 1/2/3 + assets`——唯一的三集剧集结构
- SOUL_CAROUSELS：**按日期命名**（`06/05 - glitter`、`06/19 - twins edition`、`07/01 - dream`）——轮播是日更栏目制
- ONE_MORE_TIME：单 `Assets` 大平层 447 条——音乐片全镜头一条流

## 一 逐项目方法画像（证据版）

### 1. NALA - Heads Drop（MV 的"胶片宪法"路线）
- **结构**：Music 1 / Videos 150 / Cover 1 / Images 12——音乐先行，视频主体，图只做角色锚。
- **提示词范式**：`@image` ×328 + 21:9 + Vision3——每条 Seedance prompt 挂 @image 引用，画幅胶片全锁。
- **Project brief 原文**："Video was generated using Seedance. Character and image work — Soul 2.0, Soul Cinema, Nano Banana Pro. The music was created using AI generation as well."——**工具分工声明**（视频/图像/音乐三条线三个工具）。
- **值得学**：MV 不需要叙事分镜结构，但需要**最严格的画面统一**——所以它的 151 条去重提示词几乎都是同一宪法的变奏。

### 2. Anime Production（图库路线做动画）
- **主力是 seedream_v5_pro（285 件图）而非视频**——先用图模型批量产出风格统一的漫画分格/角色表，再用 Seedance（119）动画化。
- `Manga` 独立文件夹——**漫画分格也是正式资产**。
- 与官方"资产先行"完全一致：`Character sheet → Location → Input → Video generations`。

### 3. Huntress's Tale（奇幻动作的"锚点极简主义"）
- 平均 3354 字符但结构极清晰：每条 = `identity anchor（角色全描述）+ creature anchor（生物全描述）+ 场景 + 动作`。
- 生物锚原文范例（#1，8589字符）：`large coiled serpentine dragon, steel-blue and silver scaled body with high-detail individual scale PBR texture, pale iridescent underbelly plates...`——**生物设计在 prompt 内逐字重申**，不依赖参考图记忆。
- SHOT1-5 文件夹 = 五个镜头逐镜头文件夹——但与 RED_FLAG 不同，**没有 staging map**，靠 prompt 内文字调度。

### 4. Higgsfield Academy（教学项目的"演示密度"）
- 平均 5286 / 42 条去重（435 件里大量同 prompt 迭代）——**同一条提示词反复重跑调参**，是教学演示的痕迹。
- `FOR MOTION` 文件夹——静态资产与"待动画化"资产分离。

### 5. The New Girl（版次管理教科书）
- `FINAL KEYFRAMES` / `FINAL GENERATIONS` 双轨——**关键帧和视频生成分文件夹收敛**。
- <<<image>>> ×629：每条视频 prompt 先列角色锚再进场景，剧集双线（正片+特别篇）互不串味。

### 6. Dusk（社区最强工程学）
- 865 资产、3 集、seedance_2_5 为主力——**全 9 项目唯一用 2.5 的**（其他人都是 2.0）。
- 平均 7055 字符、最长 22691——直接采用官方 16 段式（原文证据：SCENE CONTEXT → ACTIVE REFERENCES → …），`NOTABLY SHORT next to <<<image_2>>>` 这类**相对身高锚**写法极细。
- **结论**：社区头部创作者已经把官方 4K 教程的 16 段式当标准用。

### 7. Soul Carousels（栏目制美学工厂）
- 133 件 text2image_soul_v2——**纯图项目**，靠 Soul 模型出轮播图。
- 按日期命名的主题栏目（glitter / twins / dream / surreal items）——**系列化生产**：一个主题跑一批，prompt 短（1695 均值）但主题词高度重复。
- 与广告系的 60:30:10 不同，这里是**"氛围词堆叠"**路线。

### 8. One More Time（音乐片一条流）
- 437 件 seedance_2_0 平铺在单个 Assets 文件夹——**无分镜结构，全片镜头顺序即文件夹顺序**。
- handheld ×90 + hard cut ×74：手持+硬切是社区默认镜头语言。

### 9. "Top Up" AD（官方教程作者的实战范本）
- SCENE1-11 + TESTS——广告 11 场逐场文件夹。
- Style 句与官方教程**逐字相同**（8K IMAX/60:30:10/180°快门/HEAVY HANDHELD），另加类型片定制：`mid-2000s practical robot suit commercials`（2000年代机甲实拍广告质感）。
- **意义**：这条项目直接验证了"教程→实战"的迁移路径。

## 二 官方 vs 社区的语法对照表

| 维度 | 官方 12 体系 | 社区高赞 9 项目 |
|---|---|---|
| 风格宪法 | 每片独创（GLOBAL LOCK/中文标签/调色板） | 直接复用教程标准句（8K IMAX 系），少数定制类型片句 |
| 参考图管理 | 命名工程学（@char_SN_Jack） | <<<image_N>>> 序号锚 + prompt 内重申 |
| 分镜组织 | staging map / 手绘图 / 16段式 | SHOT 编号文件夹或 FINAL 版次文件夹（无示意图） |
| 提示词长度 | 平均 2-6K | 两极化：1.7K（美学流）~ 7K（DUSK 全锁流） |
| 迭代管理 | 版本即资产 | TESTS 文件夹 / FINAL 前缀 / 同 prompt 高频重跑 |
| 工具链 | Claude Skill + 全家桶 | 同款全家桶（Soul/Cinema/Nano Banana 分工声明） |
| 独有创新 | 体系化锁定 | 相对身高锚（DUSK）、栏目制日更（CAROUSELS）、音乐先行（NALA） |

**核心结论**：官方教程的语法就是社区的"通用语"。社区高赞项目的差异化不在语法，而在**题材勇气**（维京断手复仇、猎魔少女战巨蛇）和**发布节奏**（日更栏目、剧集连载）。

## 三 可复用模板（社区版）

### 模板 A · MV 胶片宪法（NALA 路线）
```
@image_1 — [角色全锚]
21:9. Shot on Kodak Vision3 500T, anamorphic. 24fps.
[镜头]：handheld / dolly / locked 三选一并写明时长
[表演节拍与音乐同步点]
HARD CUT / One unbroken take（每条二选一）
```

### 模板 B · 奇幻动作锚点式（HUNTRESS 路线）
```
Same character as <<<image_1>>> — identity anchor: [角色逐字全描述]
Same creature as <<<image_3>>> — [生物逐字全描述]
[场景一句话] [动作逐拍] [hard cut 分段]
```

### 模板 C · 短美学 prompt（CAROUSELS 路线）
```
[主题词×2-3] + [氛围词堆叠 3-5 个] + [材质/光一句话]
（例：glitter + dream + iridescent + soft haze + studio light on ...）
```

### 模板 D · 剧集版次管理（NEW_GIRL 路线）
```
文件夹：FINAL KEYFRAMES（收敛关键帧）/ FINAL GENERATIONS（收敛视频）/ SCENE-N（在制）
提示词：ACTIVE REFERENCES 全部 <<<image>>> 锚 → 场景 → 动作 → hard cut
```

## 五 补充：教程作者的 2 个教学型实战项目（赞数门槛例外）

扫创作者博客时发现 @adilinthewild（4 篇官方教程作者）的 2 个实战项目，新发布低赞但教学价值极高：

### TV_4K — Ultra Realistic AI Short Film Breakdown（1992 件）
- **47 folder 的教学结构**：FOR BREAKDOWN / ITERATIONS / YT_Gens / 10_mom / 6_winter_in_TV / 8_tv_skiping —— **"影片内场景编号 + 拆解区 + 迭代区"**，比社区项目多出两层：一个是给 YouTube 视频专用的 YT_Gens，一个是显式命名的 ITERATIONS。
- 模型：seedance_2_0 ×1040 + soul_cinematic ×701 —— Soul 系做关键帧再 Seedance 动画化。
- 最长提示词 21,521 字符（雪地卡车逃亡 + 冰怪追击）用 SCENE CONTEXT 16 段式 + **uuid 形式的资产引用**（`<<<78679d77-...>>>`——直接用 asset id 做 identity anchor，比 <<<image_1>>> 更接近工程化）。

### 4K_BLOCKBUSTER_BREAKDOWN（13,491 件，全站最大单项目）
- **剧情设定**：一个哥哥被绿色按钮困进妹妹的 AI 生成世界，每次死亡醒来换一个世界——**"片中片循环"结构**（与 4K 电视教程的频道切换同宗，但成片化）。
- **157 folder 的生产结构**：SCENE 1-4（Pirates/Jungle/Room/Desert 四个"妹妹的世界"）× FINAL GENERATIONS / FINAL ASSETS / ALL GENERATIONS / 4K tests / 1080 Tests —— **"场景×分辨率×版本"三维矩阵**，官方项目里都没见过这么细的。
- **模型分布**：soul_cinematic ×6412（图先行占近半）+ seedance_2_0 ×4558 + soul_cinema_studio ×1013 + nano_banana_2 ×648 —— 图:视频 ≈ 1.2:1，先海量出图筛选再动画化。
- **1,076 条去重提示词**：单项目去重量超过此前 9 个高赞项目之和。
- **93.7 万 credits** 的实耗成本参考：全片成本结构首次可见。

### 对九项目总纲的修正
- 〇 节统计表加一行：4K_BLOCKBUSTER（0 赞/新发布/13491 件/平均长度未统计）——**资产量与赞数无关**，教学型项目走的是 YouTube 视频带货路线（Breakdown = 配视频的项目库）。
- 二 节对照表补一行：**版本×分辨率矩阵**（FINAL/ALL GENERATIONS + 4K/1080 Tests）是教程作者独有的生产管理法，官方项目里未见。
